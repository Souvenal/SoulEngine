# Context: RenderGraph

**Namespace:** SoulEngine

RenderGraph module: a per-frame `RenderGraphBuilder` plus a module-level `RenderGraph` singleton (ADR 05). On the builder, a pass's nested `Parameter` struct IS its resource declaration — view-typed fields derive accesses at `AddPass` via a compile-time aggregate walk (no reflection, no second list). A single `Compile()` orders, prunes, acquires live transients from the pool, binds surviving pipelines, and moves the surviving passes into a `RenderPassList`. Cross-frame facilities — graphics/compute pipelines (PipelineRegistry) and the transient texture pool (RGTexturePool) — live on the `RenderGraph` singleton, not on the per-frame builder object.

## Language

**Parameter**: A pass's nested aggregate struct. View-typed fields declare how the pass accesses resources; every other field (samplers, bindless arrays, CPU scalars) is passthrough and declares nothing. `AddPass<TPass>(Parameter&&)` takes ownership: the Parameter moves to a heap home whose address stays final, the graph collects pointers to its view fields (the traversal record that ordering, pruning, usage check, and prologue consume — declaration fields live in exactly one place), and the constructed pass owns the `UPtr<Parameter>` from registration on. After AddPass the Parameter is frozen — wiring ran before the call. _Avoid_: separate Declare/record callback pairs, per-pass author-written lambdas, storing view field copies in the pass node

**View**: A Parameter field type AND the access declaration in one type (ADR 05): `RGTextureView<Usage, Access>` / `RGBufferView<Usage, Access>` — role (RHI usage bits) and access ride the template arguments, so the wiring site initializes each field by name with the `RGTexture`/`RGBuffer` identity alone (`{.Output = Target}`) and a whole-record assignment is ill-formed (the declared role cannot be reset). Both templates derive from the erased records `RGTextureViewData` / `RGBufferViewData`: identity → role (`Usage`) → extent (`Range`) → `Access` → `Resolved`, the one non-template shape the graph's pointer tables, sync planning, and usage checks all consume (the aggregate walk detects views by `derived_from` these records). At Compile the graph resolves `.Resolved` — the realized or imported resource ref is the only payload Compile adds; role/extent/access stay in the declaration fields as the single source of truth. `Record()` consumes `.Resolved` directly for commands and readiness checks, and builds the ready RHI view on demand via `ResolvedView()` for attachments and bindings; passes never rebuild views by hand beyond that accessor. Acceleration structures have no view: BLAS/TLAS builds are frame-start device work carried by `RenderResult`, not graph passes; samplers/TLAS bind through a one-role object form. _Avoid_: AccessFields-style parallel declaration lists, restating role/access at the wiring site

**Usage**: The usage axis of an access declaration: how the pass touches the resource (sampled, storage, constant, indirect, attachment, copy). ADR 05 unifies this axis with the RHI creation vocabulary — declarations yield `RHITextureUsage`/`RHIBufferUsage` bits directly, one role per view; creation usage stays explicit at CreateTexture/CreateBuffer, and a view's declared usage must remain a subset of it (supersedes the short-lived `RGUsageKind`). Combined with Access and the pass's stage class it fixes the state a transition requests — including image layout, which has no other source. Resource kind is NOT part of this axis; handle types already carry it (ADR 05). _Avoid_: flattened usage enums that bake resource kind into access values

**Access**: The Read/Write axis of an access declaration (`RHIAccess`, RHI-level) — "access" in Vulkan's sense (VK_ACCESS_*_READ/WRITE). The only axis ordering and pruning consult (last-writer chain, side-effect writes). A loadOp=Load attachment is `Read | Write`, not Write. A shader that read-modify-writes (atomic append, counters) declares `Read | Write` likewise — the backend translates the declared direction faithfully, with one mechanism exception: depth/stencil attachment coverage is always Read|Write (a load reads, the store writes). Not derivable from Usage: buffer SRV and UAV share `RHIBufferUsage::Storage`. _Avoid_: separate read/write view-type pairs where a direction flag suffices

**Stage class**: The coarse pipeline class a pass belongs to — Graphics, Compute, RayTracing, Transfer — known statically from its RHI pass base type at AddPass. Combined with Usage and Access it fixes a transition's stage/access without shader reflection. _Avoid_: reflection-derived stage inference at Compile

**Prologue transition**: A destination-only state requirement the graph attaches to each surviving pass at Compile: every declared access mapped to the state the pass needs that resource in before its commands run. A transition is a declaration, not a barrier — it carries no src/dst pair; the backend's diff tracker materializes a barrier only when tracked state differs (ADR 05). The declaration contract: a pass must declare every graph resource it touches, including BDA pulls and indirect buffers — undeclared access is a pass-author bug surfaced by validation. _Avoid_: inferring synchronization from binding side effects or reflection, graph-side cross-frame state tables

**Identity** (`RGTexture` / `RGBuffer`): Passive index into the graph's resource table. Two kinds only, mirroring the RHI resource convergence (ADR 05); lifetime flavor is the entry's business. Cheap to copy, invalid by default, no ownership. _Avoid_: generation counters, a common handle base type

**Last-writer chain**: The ordering rule. A reader orders after the resource's latest writer; a writer orders after the previous writer and every reader of the previous state. Independent passes run in registration order. A pass never depends on itself. _Avoid_: resource version numbers, full pairwise dependency graphs

**Prune**: Dropping passes that do not contribute to the frame. A pass is required when it has a **side effect** — `static constexpr bool NeverPrune` on the pass type or a write to an imported resource (visible outside the graph) — or when a required pass transitively depends on it. `BlitToSwapchainPass` writes only the backend-private swapchain, so it carries `NeverPrune`. Everything else is dead code: dropped with its node, and its transients are never realized. Terminology: prune, never "cull" (culling is the renderer's visibility concern). _Avoid_: MarkSideEffect runtime calls, keeping dead producers alive "just in case"

**Pipeline prune**: At Compile, a pipeline pass whose async pipeline is still Pending is dropped together with every required pass depending on it. Dropping a side-effect pass means the frame cannot produce its required output: Compile returns an **empty RenderPassList** (soft degrade, not an error). A Failed pipeline on a required pass is a hard frame error. An unregistered pipeline pass is a hard error. Dead passes are pruned before their pipeline is ever queried. _Avoid_: renderer-side readiness snapshots as inclusion gates

**Single Compile**: `Compile() -> std::expected<RenderPassList, ErrorMessage>` is the only entry point: it validates, orders (last-writer chain), prunes (side effects, then pipelines), acquires live transients from `RGTexturePool`, resolves view `.Resolved` refs through the collected view pointers, maps each surviving pass's accesses into its prologue transitions, and binds surviving pipelines. No separate Execute step; a graph compiles exactly once — rebuild it every frame. `Record()` is invoked later by the RHI thread, never by Compile. _Avoid_: two-phase Compile/Execute APIs, Record calls from the graph

**Constructor injection**: A pass is constructed at AddPass as `TPass(UPtr<Parameter>)` and lives on its node from then on; the graph collects the view pointers into its Parameter right after construction. A pipeline pass (`TPass::BuildPipelineRequest()` exists) is born without its pipeline — readiness cannot exist before Compile — and the graph binds the registry's Ready ref at Compile through the RHI pass base's `BindPipeline`, down-casting on the node's stage class. _Avoid_: shell/template pass classes, per-frame pass-author construction code, ctor-time pipeline injection

**Pass type erasure**: After AddPass the graph knows TPass only as the `IRHIPass` base behind the node's `UPtr<IRHIPass>`; everything else it needs is copied at registration as static markers (NeverPrune, HasPipeline, StageClass, PipelineKey), and ordering, pruning, usage checks, and the prologue consume the view pointer lists. A pass ctor is written in-class like any other; BlitToSwapchainPass, whose AddPass call site lives in another module, links with an in-class ctor (verified by clean rebuild + link on clang 23). _Avoid_: void*-and-deleter Parameter storage, construction thunks, copying the Parameter into the node, out-of-line ctor definitions for emission reasons

**Graph-created transient**: `CreateBuffer` / `CreateTexture` take the RHI descriptors directly (one vocabulary) and register them only. An entry's kind lives in a `std::variant<RGBufferProp, RGTextureProp>` payload (the two kinds are mutually exclusive); origin is the separate `IsImported` flag, and `AsGraphTexture()`/`AsGraphBuffer()` bundle the (kind x graph-created) check every consumer wants. Entries are born complete through four constructor overloads (kind x origin). Note the two "transient" vocabularies: RHI-desc `Lifetime` is the backing resource's lifetime (belt slice in the VK backend), while graph-created means RG-pooled — pooled resources are RHI-persistent. Graph buffer pooling does not exist yet, so `CreateBuffer` validates `Lifetime == Transient` (belt slice) until it does; Compile acquires the RHI object (textures from `RGTexturePool`), and only if a surviving pass touches the resource. `Usage` is declared at creation (required, forwarded verbatim) — what the resource may be used for is the creator's call (ADR 05); Compile checks every surviving view's role against it and fails the frame on under-declaration. The buffer uniform/storage belt split keys on the creation usage's Constant bit. Texture InitialData is rejected until the graph grows an upload path. Buffer InitialData is a separate `CreateBuffer` parameter (RHI buffer Descs never carry data — bytes flow exclusively through `UploadBuffer`): it is the resource's initial content and says nothing about how passes view the resource. The graph copies the bytes at registration (callers may hand in spans over temporaries that die before Compile) and realize issues CreateBuffer + UploadBuffer — the upload task writes the belt slice in place, after the creation task materialized it (same-frame frame tasks run FIFO). Reading a transient nobody wrote is legal: no InitialData means undefined scratch contents, which is the caller's concern, not the graph's. InitialData size must equal SizeBytes (mismatch: invalid handle). _Avoid_: realizing dead transients, caller-lifetime InitialData spans reaching realize without a graph-owned copy

**RenderGraph singleton**: Module-level owner of cross-frame facilities: `PipelineRegistry`, `RGTexturePool`, `Tick()`, and `Shutdown()`. `Tick()` runs in RenderLoop immediately before `IRenderer::Render()` and evicts pool entries idle for 10 consecutive frames (LRU by frame age). `Shutdown()` clears the pool and the registry before `RHIRenderDevice::Destroy()` (root shutdown-boundary constraint). _Avoid_: per-frame pool instances, GPU-completion gates on pool return

**RGTexturePool**: Cross-frame reuse of transient textures: `{desc hash (format + extent + creation-declared usage) → free list}`, exclusive acquire within a frame. Return is immediate when a replaced RenderResult's pass list is destroyed — no GPU-completion gate. Safety invariants: single-queue submission ordering and per-frame image state initialization (ADR 05). _Avoid_: pooling inside the RHI backend, pool keys without usage bits

**Blit to swapchain**: The only present path. `BlitToSwapchainPass` (`NeverPrune`, transfer pass) issues `RHIBlitToSwapchainCmd{Source, DstRect}`; the backend visitor always blits the complete source target into the acquired swapchain image with a fixed Nearest filter. The dst rect comes from the camera's Viewport. There is no present flag on passes, views, or usage bits. _Avoid_: SetPresentOutput, `.Present` bits, FrameOutput usage, backend-implicit present blits

**Import**: Registering an externally-owned RHI object (render target, readback buffer) with the graph. Imported resources are never realized; writes to them are side effects (visible outside the graph). Imported views join the prologue like graph-created ones, and the usage check answers from the realized RHI object's creation usage (ADR 05). _Avoid_: importing graph-created transients, per-frame transient imports as a test crutch (tests use a factory-registered mock device instead)

**Aggregate walk**: The compile-time enumeration of a Parameter's fields: brace-acceptance arity probe (cap 16 fields) + structured bindings, recognizing the two view types directly. A macro generates the per-arity binding boilerplate; it is never exported from the module. _Avoid_: reflection libraries, hand-written per-pass field lists

**Testing**: RenderGraph tests run without a GPU: a `MockRenderDevice` (base `RHIRenderDevice` defaults + counting transient-create overrides) is registered in the backend factory as `"Test"` and created through the normal `RHIRenderDevice::Create` path. RHIRenderDevice methods are non-pure virtuals with "not implemented" defaults exactly so tests can subclass the base directly. _Avoid_: test-only singleton injection setters, pure-virtual RHI interfaces that force 26-method mocks
