# Context: Vulkan

**Namespace:** SoulEngine

Vulkan RHI backend. It is the current concrete implementation of the FrameSlot-owned RHIRef contract described by the RHI context.

## Terms

| Term | Definition |
|------|------------|
| **Graphics timeline** | Device-level timeline semaphore signalled by every frame submission. RHIFrameCompletion stores the corresponding completion value. |
| **Frame completion** | Backend-independent token returned by EndFrame(); RenderThread waits on it before replacing the slot-owned RenderResult. |
| **BeginFrame** | Waits for reuse of the backend frame context and resets frame-local scratch/descriptor state. Transient belts need no reset: their rings retire and seal through the frame-begin Tick chain. |
| **Deferred deletion queue** | Two hops with distinct jobs. The RHI-module-owned queue behind GDeferredDeletionQueue is the cross-thread transport: final RHIRef release enqueues the native destructor from any thread, RHILoop drains it on the RHI thread after Tick() via DrainRHIDeferredDeletions(), and Shutdown() performs the final drain. The drained destructor feeds the backend deferred deletion queue below rather than destroying in place. |
| **Backend deferred deletion queue** | `VulkanDeferredDeletionQueue` (:Context), owned by the resource context — the GPU-retirement hop for VMA buffers and images (VulkanBuffer, VulkanReadback, VulkanTexture, and self-owned internal storage such as acceleration-structure storage and the ray-tracing shader binding table). Destruction is a virtual timeline event: Enqueue stamps the entry {RetireValue, Kind, Handle, Allocation} with a fresh host value that no submission ever signals directly, and the monotonic device counter covers it once the next real submission completes. Sound because no new command can reference a resource after its last ref is gone, so the destruction frame's own submission upper-bounds the last GPU use. Entries retire from the front in the device Tick(); Shutdown() flushes unconditionally while the device is idle. This replaces frame-slot retention: resources referenced outside the command list (upload-batch destinations, BDA-pulled geometry buffers) need no manual retention. |
| **Transient belt** | `VulkanUniformBelt` / `VulkanShaderStorageBelt` (:Buffer) — typed per-frame allocation lanes over `VulkanRingBuffer`, owned by the buffer manager (wgpu StagingBelt vocabulary: a belt is a ring allocator facade; unlike the staging belt these carry no batch — CPU writes bind through dynamic descriptors, there is no command-side work). Each belt configures its ring with the usage union and device alignment of its kind (uniform: `eUniformBuffer` + `minUniformBufferOffsetAlignment`; storage: `eStorageBuffer|eIndirectBuffer` + `minStorageBufferOffsetAlignment`) and range-checks every allocation against `maxUniformBufferRange` / `maxStorageBufferRange`. A slice caches its whole `RingAllocation` (buffer, mapped base, offset), so a mid-frame ring growth with two live instances is unambiguous, and binds through dynamic descriptors with the absolute offset. Growth and retirement inherit the staging-ring contract (grow-only, frame-begin seal, timeline-marker retirement). Each belt bumps a generation counter at every frame-begin Tick and slices stamp their creation generation: a cross-frame upload — a transient ref retained past its creation frame, a contract violation the frame-task ordinals cannot see because the misused upload's task ordinal still matches the current frame — is dropped with a warning instead of corrupting a recycled or in-flight range (stale *tasks* are already discarded by TaskGraph; the guard covers target vintage, not scheduling). Capacities are total ring sizes from the `RHI.Vulkan.UniformBeltSize` / `RHI.Vulkan.ShaderStorageBeltSize` CVars (bytes), read once at device init. RHI-thread confined. |
| **Staging ring** | `VulkanRingBuffer` (:RingBuffer) — a wrap-around bump-allocation ring over VMA buffers, created in one of two memory classes: HostMapped (host-visible, contractually host-coherent, persistently mapped — the staging and transient belts and the AS instance ring) or DeviceLocal (GPU-only working memory — the AS scratch ring); the staging source for the frame-start upload batch (GpuOnly UploadBuffer uploads and mip-0 UploadTexture uploads, via the device-owned staging belt), and the shared allocation machinery behind the transient belts. Every ring is created with a usage union and an allocation alignment (floor 4 = the `vkCmdCopyBuffer` offset requirement; descriptor-bound consumers pass their device limit). Retirement is frame-granular and rides the frame-begin Tick: the device Tick reserves one frame-begin timeline value per frame (`IncreaseHostValue` — strictly above every submitted value so far, strictly below the next submission's signal value, so the next real submission covers it) and forwards it down two chains — device `Tick()` → `VulkanBufferManager::Tick(value)` → uniform/storage belts, and device `Tick()` → `VulkanStagingBelt::Tick(value)` → staging ring; every chain ends in `VulkanRingBuffer::Tick(value)`. The ring first retires every marker the device graphics timeline counter has passed (freeing ranges for the new frame's allocations), then seals the previous frame's pending allocations by pushing one `<frame-begin timeline value, head offset>` marker (only when the frame allocated). Sealing at frame begin marks the previous frame's end, so recycling lands one frame later than stamping at the submission itself; a failed frame adds no hazard, only later retirement. The bump head may wrap only past retired offsets, and `Head == Tail` means empty (an exact-fill placement diverts to growth). Failure to fit triggers generational growth — a larger replacement buffer takes new allocations; a superseded instance receives no further allocations, so it is simply stamped with the frame-begin timeline value at the seal and destroyed once the device timeline passes the stamp (grow-only, never shrinks, uncapped beyond allocation failure, which fails soft per entry). Initial capacity comes from the `RHI.Vulkan.StagingRingBufferSize` CVar (bytes), read once at device init. RHI-thread confined. |
| **Staging belt** | `VulkanStagingBelt` (:Staging) — the frame-start upload staging lane: the staging ring plus the pending buffer and image lanes, owned by the render device and borrowed by both resource managers. Upload frame tasks enqueue payload-blind entries (destination handles and access masks are snapshotted at enqueue, so batch recording never resolves payloads again); Execute records the batch into its own dedicated secondary (buffer copies with one aggregated transfer-write → consumer-read barrier; mip-0 buffer→image copies wrapped in image-tracker transitions; per-lane debug labels; a no-op on an empty batch, so the device records unconditionally). A staging failure is fail-soft per entry (logged; the upload is re-issuable). Ring ranges retire via the ring's timeline markers; destinations need no retention — their native destruction rides the backend deferred deletion queue. RHI-thread confined. |
| **Buffer manager** | `VulkanBufferManager` (:Buffer) — the home of buffer concerns (Desc validation and creation dispatch: persistent / transient slice; frame-affined buffer uploads; the transient belts `VulkanUniformBelt` / `VulkanShaderStorageBelt`). All fallible construction lives here: `CreatePersistentBuffer` performs the persistent VMA allocation itself and publishes Ready synchronously, `CreateTransientBuffer` enqueues the frame task that resolves the belt range and publishes; `VulkanBuffer` is a pure payload whose two Prop-typed constructors are infallible assignment (no static factories), so flavor state is written exactly once at construction. | GpuOnly upload bytes stage through the device-owned staging belt, which the manager borrows. Both transient belts sit behind the manager's frame-begin `Tick(value)`. The render device holds one and forwards; its state is RHI-thread confined. Desc validation is backend-local by design — tolerance is a backend decision, so `RHIBufferDesc` stays a pure data carrier. Transient belts are contractually host-coherent (ring creation fails otherwise) — host writes are implicitly visible to later submissions, so no HOST-stage barrier exists anywhere. |
| **Texture manager** | `VulkanTextureManager` (:Texture) — the home of texture concerns (creation dispatch and the frame-affined UploadTexture front-end), mirroring the buffer manager. Upload frame tasks stage mip-0 texels through the device-owned staging belt's image lane, which the manager borrows. The render device holds one and forwards; the upload task is RHI-thread confined. |
| **AS manager** | `VulkanAccelerationStructureManager` (:AccelerationStructure) — the home of acceleration-structure concerns (BLAS/TLAS creation, the frame-affined BuildBlas/BuildTlas front-end, and the frame-start build batch), mirroring the buffer and texture managers. Creation materializes the payload synchronously on the calling thread (validation, geometry/instance baking, the build-size query, storage/handle/address allocation — VMA and the device-level calls are thread-safe); Build calls enqueue frame-affined tasks that append a baked, self-contained build entry to the manager's pending lists at the RHI thread's frame-task drain; `RecordBuildBatch` drains them at Execute (no-op when empty) and records with zero device calls — a ring carve plus command emission per entry. Owns two rings: a device-local **scratch ring** (`eStorageBuffer | eShaderDeviceAddress`, alignment = `minAccelerationStructureScratchOffsetAlignment`, the `RHI.Vulkan.ASScratchRingSize` CVar) that every BLAS batch entry and TLAS build bump-allocates its scratch range from, and a host-mapped **instance ring** (`eAccelerationStructureBuildInputReadOnlyKHR | eShaderDeviceAddress`, 16-byte alignment, the `RHI.Vulkan.ASInstanceRingSize` CVar) that stages each TLAS's packed instances — host-coherent, so the memcpy is implicitly visible to the frame's submission without a HOST barrier. `RecordBuildBatch` records the BLAS batch then the TLAS builds into a dedicated frame-start secondary; both rings retire through the frame-begin Tick chain. The rings materialize only when hardware ray tracing is available. The render device holds one and forwards; the build phase is RHI-thread confined. |
| **Swapchain image** | Backend-private image acquired for presentation. The `RHIBlitToSwapchainCmd` visitor transitions it and blits the command's source render target into it at the command's explicit dst rect (fixed Nearest filter); the ImGui overlay may then load-and-render on top. It is never an engine-owned RHIRef payload. |
| **Image tracker** | Device-level per-subresource state tracker keyed by (image, aspect bit, mip, layer). Stores no image metadata: every call site resolves concrete subresource ranges from the payload it already holds, so creation never touches the tracker and it stays purely RHI-thread confined. `Transition(range)` emits one barrier per differing subresource — no whole-image over-sync, no coalescing (all engine images have arrayLayers == 1). `Seed` exists only for images whose initial state is not Undefined (swapchain images seed their transfer stage); `Forget` runs at destruction (RHI-thread deferred drain) against driver handle reuse. |
| **Vulkan object naming** | Application-defined `VK_EXT_debug_utils` labels assigned through `VulkanDebugUtils::SetObjectName`. Every Vulkan handle created or allocated and owned by SoulEngine, including internal handles, is required to receive a deterministic name after successful creation. |

## Debug utilities and object naming

`VulkanDebugUtils` is the only supported path for assigning `VK_EXT_debug_utils` object names. Callers must not invoke `setDebugUtilsObjectNameEXT` directly. The service intentionally becomes a no-op when debug utils are disabled or unavailable, when the name is empty, or when the handle is null; these cases do not require caller-side branching. Whether names are consumed on the driver side is subject to the `RHI.Vulkan.DebugUtils` configuration; the producer-side obligation to call `SetObjectName` is unconditional.

Every Vulkan handle created or allocated by the backend and retained by SoulEngine must be named immediately after successful creation, before the handle is moved into its owning object. This includes persistent RHI resources, their backing and auxiliary objects, and internal objects such as frame contexts, descriptor resources, swapchain resources, and shader modules. Handles borrowed from an external owner are not owned creation sites and are not renamed by this contract.

Persistent RHI resources use their logical RHI name as the base name. Derived native objects use the following grammar:

- `Base` identifies the primary native object.
- `Base#Role` identifies backing or auxiliary storage, such as an image, staging buffer, scratch buffer, or shader binding table.
- `Base::Role` identifies related Vulkan state, such as a pipeline layout or descriptor-set layout.
- `Internal/<Type>/<Role>/<Instance>` identifies RHI-internal objects, with the Vulkan object type immediately after `Internal/`.
- `<Usage>/<Type>/<LogicalPath>` identifies RHI resources visible outside the Vulkan backend.

Examples:

```text
Internal/Instance
Internal/Device
Internal/CommandBuffer/Primary/Frame0
Internal/CommandPool/Secondary/Frame0
Renderer/RenderTarget/View0/SceneColor
Renderer/GraphicsPipeline/GeometryPass
```

Names must be deterministic, non-empty, and describe the object's role. New creation sites must follow this grammar instead of introducing ad hoc delimiters.

The current implementation does not yet satisfy this contract at every creation site. Known follow-up coverage includes swapchain image views and semaphores, shader modules, and descriptor-pool/set objects. Until those sites are updated, this document describes the required target behavior rather than claiming complete runtime coverage.

## Frame submission lifetime

VulkanRenderDevice::Execute() validates and records a ref-backed command list borrowed from the producer FrameSlot. EndFrame() submits the primary command buffer and returns an RHIFrameCompletion token; it does not retain or move the list. RenderThread waits on that token immediately before replacing the slot's RenderResult, so the list's RHIRefs remain alive while the submission is in flight.

TLAS is per-frame: the renderer creates a fresh TLAS each frame — creation packs the instances and materializes storage sized to the instance count — and the AS phase builds it once. There is no persistent TLAS backing and no capacity; the storage retires with the object through deferred deletion, while the build's scratch and instance ranges are bump-allocated out of the AS manager's rings and retire via the rings' frame-seal timeline markers.

## Threading and lifecycle

- Normal runtime sampler native creation is enqueued to ThreadQueue::RHI by EnqueueResourceCreation; RHILoop drains that queue before Tick() and Execute(). Persistent-buffer and texture creation are synchronous on the calling thread (thread-safe: VMA locks internally, vkCreateBuffer/vkCreateImage are device-level), as are pipelines, binding sets, and BLAS/TLAS payloads (their Create performs the size query and storage/handle/address allocation — VMA and the device-level calls are thread-safe). Buffer uploads ride frame-affined UploadBuffer tasks, drained before Execute, and dispatch on the buffer's RHIMemoryUsage: CpuToGpu payloads get an RHI-thread vmaCopyMemoryToAllocation straight into the host-visible allocation (no staging, no batch entry); GpuOnly payloads bump-allocate a staging-ring slice and host-copy into it in the task, and Execute records the upload batch (one copy per entry, one aggregated transfer-write barrier) into its own dedicated frame-start secondary, ahead of the BLAS batch's own secondary; the BLAS batch reads those geometry buffers; consumed ring ranges retire via the ring's timeline markers, and destination buffers need no retention — their native destruction rides the backend deferred deletion queue. Texture uploads (UploadTexture frame tasks) stage through the same belt's image lane (ring slice + host copy): the batch wraps each buffer→image copy in image-tracker transitions (→ TransferDst → ShaderReadOnly; the tracker supplies the current layout, so re-uploads transition correctly), and image destinations share the no-retention contract — the deferred deletion queue covers VMA images. Ray-tracing pipeline creation is likewise synchronous; its shader binding table is self-owned device-local storage whose packed bytes ride a frame-affined task into the upload batch's buffer lane (an explicit-access entry, eShaderRead), so a same-frame trace pass is safe by submission order. VulkanBuffer expresses its two lifetime flavors as std::variant<PersistentBufferProp, TransientBufferProp> — the persistent flavor owns its allocation directly and derives transfer-dst plus BDA from GpuOnly placement, the transient flavor borrows a belt range (TransientBufferProp::Allocation, a RingAllocation) and owns nothing; GetProp<T>() is the only flavor-state access path (there is no GetOffset — transient callers fetch the absolute offset through GetProp<TransientBufferProp>()->Allocation.Offset and fail loud on the wrong flavor); VulkanDeviceBuffer remains for AS storage/scratch only. AS builds stay orchestrated data-driven from RenderResult's pending lists through static Build entry points on the AS payloads (no AS command types — ADR 05): the BLAS batch shares one alignment-split scratch; each TLAS owns an aligned persistent scratch.
- Command pools, descriptors, transient belts, and queue submission are RHI-thread confined during normal operation. WaitFinish() is the explicit exception: it performs only a read-only host wait on the device timeline and is callable from RenderThread.
- Initialization and shutdown remain main-thread lifecycle exceptions today. Shutdown() waits idle, drains deferred deletion, then releases Vulkan contexts. No RHIRef may outlive this sequence.
- The ImGui overlay command contains borrowed ImGui data valid only through Execute(); it is not retained by the backend after submission. Dear ImGui owns its own texture lifetime.

## Relevant partitions

| Partition | Responsibility |
|-----------|----------------|
| :RenderDevice | Device bootstrap, frame execution, timeline retirement, resource-creation task enqueueing, shutdown |
| :Command | RHICommand visitor and Vulkan command recording from ready RHIRef payloads |
| :RingBuffer | Ring allocator shared by the staging belt, the transient belts, and the AS manager's rings |
| :Staging | Device-owned frame-start upload staging: the staging ring plus the pending buffer and image lanes |
| :Buffer, :Texture, :Pipeline, :RayTracingPipeline, :AccelerationStructure | Native payload implementations created and ultimately destroyed on the RHI path; :Buffer, :Texture, and :AccelerationStructure also hold the resource managers |
| :Descriptor, :Swapchain, :Semaphore, :Types | Backend descriptor, presentation, synchronization, and conversion/state support |

## Guardrails

- Keep FrameSlot.RenderPacket alive until both RHI CPU consumption and its RHIFrameCompletion timeline have completed; replacement is the retirement boundary.
- Do not enqueue a native destructor directly from a Game or Render thread. Use RHIRef final release and the deferred-deletion queue.
- Do not reuse transient belt memory or a Vulkan frame context before its timeline wait completes.
- Do not add a second backend without an equivalent RHIFrameCompletion wait implementation that is safe to call from RenderThread.
