# Windows MSVC modules diagnostic reference

Load this reference for Windows x64 builds using MSVC, Xmake, and C++ named modules. Use the exact failure signature to choose the smallest repair. Rebuild from clean generated artifacts after interface, runtime, or toolchain changes.

| Signature | Likely cause | Repair | Do not do |
| --- | --- | --- | --- |
| `C7631` says an anonymous-namespace variable was declared but not defined while compiling an importing module | An exported `inline` function referenced module-private state, so the importer compiled an inline body that could not link to the internal-linkage object. | Make the exported function non-inline so its body is emitted only by the owning module, or move the state behind a non-inline module-local accessor. | Export a module-private variable, give it external linkage only to satisfy the importer, or rely on a transitive module import to preserve internal linkage. |
| `LNK2001` for an exported module `inline` variable despite its definition being compiled (for example `GDeferredDeletionQueueStorage`) | MSVC 14.51 can emit a force-include directive with a different module-mangled name from the definition of an exported `inline` variable. | When one module partition is the sole owner, remove `inline` and keep one non-inline module definition; clean/rebuild the producer and final executable. | Add a duplicate definition in an importer, suppress the linker error, or change target dependency order. |
| `C1083` cannot open `hlsl++.h`, or `hlslpp::float3` and related math symbols are missing in a module that imports `Scene` | The module directly uses hlsl++ declarations or inline math, but its target does not declare the `hlslpp` package. A Scene import does not make the header dependency available to the consumer's global module fragment. | Add direct `hlslpp` through `add_packages`; make it public when the module exports hlsl++ types. Include `<hlsl++.h>` in the consumer's global module fragment, then clean, configure, and rebuild. | Rely on another module's public package declaration, or remove the include and expect a named-module import to expose the hlsl++ header API. |
| EnTT `type_traits.hpp(149)` / `meta/factory.hpp` fails while registering a reflected property with a getter and setter | `meta_factory::data` received getter and setter template arguments in the wrong order. EnTT 3.16 declares the template as `data<Setter, Getter>`. | Register `data<&Type::SetValue, &Type::GetValue>(id)`, then validate the load/save path through the relevant scene tests. | Assume a getter-first order from a different reflection API, or expose nested component storage directly only to preserve a flat serialized field. |
| LLVM Clang 22.1.7 compiler internal error while compiling SoulEngine modules | The tested Windows Clang path remains blocked by a compiler failure after the earlier module/STL issues are addressed. | Keep Windows on the configured MSVC path. Reconsider Clang only after the internal error is fixed upstream or otherwise resolved; then validate `test_std/` and a clean full-engine build. | Treat the earlier concepts/type-traits workaround as a complete Clang fix. |
| `std::same_as`, concepts, or traits missing under Windows Clang | Windows Clang + MSVC STL named-module integration did not expose the facility reliably. | Keep Windows on the configured MSVC path. Use `test_std/` before considering Clang support again. | Add `<concepts>` / `<type_traits>` to project module global fragments while the MSVC path is active. |
| C1116 inside `<stop_token>` while importing `std` | A module unit textually included spdlog (or another header that brings in standard-library headers) and also imported named `std`; MSVC saw conflicting standard-library representations. | Isolate the integration in a conventional `.cpp` backend and bridge it with private C ABI declarations. `CoreLoggingBackend` is the pattern. | Include spdlog in `Core:Logging`, remove `import std` from the module, or hide the error with compiler flags. |
| C2079 at `<istream>:698` says `basic_istream::sentry` is undefined while compiling a module that imports `Core` and `std` and textually includes Slang COM headers | MSVC 14.51 can leave the nested `basic_istream::sentry` incomplete when an inline `ReadFile()` body using `tellg()` is materialized after named `std` import; `slang-com-ptr.h` textually includes STL headers before that import. `std::span<const Path>` is only the trigger site. | Add `<fstream>` to the importing module's global module fragment before Slang headers/imports; keep `Core:Util.IO`'s `module;` and `export import std;` ordering so the IO interface uses the named STL consistently. Clean/rebuild the affected module target. | Change `std::span`, remove `tellg()`, or treat this as a Slang API/type error. |
| `LNK2038` for `_ITERATOR_DEBUG_LEVEL` or `RuntimeLibrary` | A static target/library used `MD`, while the Debug application/named `std` module used `MDd` (or the reverse). | Set Debug `MDd`, non-Debug `MD`; clean and rebuild the backend plus dependent targets. | Link with `/NODEFAULTLIB` or mix CRTs deliberately. |
| C2461 around a member declaration such as `Uint32 Binding = 0;` inside `struct Binding` | The member name collides with the enclosing type name; MSVC parses it as constructor-like syntax. | Rename the numeric field to `BindingIndex` and update producer, consumer, and tests. | Rename a widely used public type when the field rename is the smaller semantic change. |
| clang-cl: `no such file or directory: '/fo'` while compiling an `.rc` file | clang/clang-cl and the Windows resource compiler were selected incompatibly by a third-party package build. | Use the configured MSVC toolchain on Windows, then clean/reconfigure the package build. | Patch package source or resource scripts before verifying the actual toolchain selection. |
| `LNK1561: must define an entry point` for a test binary although `gmock_main.lib` appears on the command line | The generated link order placed gmock main before test object files, so its archive member was not selected. | Keep `gtest[main]`; on Windows add `/WHOLEARCHIVE:gmock_main.lib` through `add_ldflags` in `test_module`. | Add a project-local `main`, add a `main` to every test source, or depend on archive ordering. |
| `LNK2019` for `glfwGetError`, `glfwCreateWindowSurface`, or `glfwGetFramebufferSize` while linking a Renderer test | The Renderer module pulls RHIVulkan object code, but Renderer keeps GLFW as a private package; the generated test target therefore lacks GLFW linkage. | Add `glfw` to that `test_module`'s `additional_packages`, then clean/reconfigure when a module interface also changed. | Make GLFW public for all Renderer consumers, add duplicate test-local GLFW stubs, or suppress the unresolved symbols. |
| `C1041` opening `compile.<target>.pdb` during parallel Debug builds | MSVC `/Zi` makes concurrent source compilations write one compiler PDB. | In Debug use `set_symbols("debug", "embed")` so MSVC uses `/Z7` and embeds debug information in each object. Clean, configure, and rebuild. | Reintroduce global module build fencing solely to serialize compilation, or require a manual prebuild. |
| `C2235` says a target's `std.ifc` has incompatible target architecture after `xmake clean --all` | Xmake retained a stale named-module IFC under `build/.gens/<target>/...`, so the normal clean did not fully reset the target's module cache. | Delete the project-generated `build/` directory after verifying its resolved path is inside the workspace, then run `xmake f -m debug -y` and rebuild. Use `xmake test -v` for a clean test graph. | Change platform/arch settings without evidence, or treat this as a source-level type error. |
| `C5050` reports `_DEBUG`/`NDEBUG`/`_MSVC_MD` mismatch followed by `C1116` importing a module after switching build modes | Xmake's project-local `cache/cxxmodules` still maps a debug consumer to release IFC files (or the reverse). | Reconfigure the requested mode, remove `.xmake/<plat>/<arch>/cache/cxxmodules`, then rebuild and run `xmake test -v`. | Delete source files, change module declarations, or accept a release-module import in a debug test target. |
| EnTT `registry.hpp(1176)` reports C2079 for `basic_registry::entities` using incomplete `basic_sigh_mixin` (or `mixin.hpp` / `storage.hpp` reports C2678 for `sparse_set_iterator`) in a module importer | An exported class has an inline lifetime/member-instantiation path containing `entt::registry`; EnTT headers in the owning module's global fragment are not reachable when MSVC instantiates that path in another module unit. Clang may accept the transitive visibility. | Give each module/translation unit that owns or destroys the registry-bearing object a direct global-fragment include of `<entt/entt.hpp>` and a direct Xmake `entt` package dependency; make the package public when downstream module consumers instantiate the exported layout. | Assume `import Scene`/`import Editor` re-exports EnTT headers, or remove inline definitions while leaving them in the primary interface: MSVC can then emit duplicate symbols. |

## Inspecting scan output

For a failing module, find its generated scan file under:

```text
build/.gens/<target>/windows/x64/debug/rules/bmi/cache/scans/
```

Open the `*.module.json` matching the source. Its `requires` list should include every directly imported named module. For an `import std;` repair, require a `logical-name` of `std`.

## Known project boundaries

- `Core:Logging` is an exported engine module and must not include spdlog headers.
- `CoreLoggingBackend` is a conventional static target that owns spdlog headers, sinks, formatting, and file I/O.
- `Windows.cppm` and `SlangTypes.cppm` intentionally import `std` directly for MSVC scan correctness.
- The old `<concepts>` / `<type_traits>` global-module-fragment additions were Windows-Clang workarounds and were removed after moving Windows back to MSVC.
- `test_module` uses `gtest[main]` and forces `gmock_main.lib` on MSVC; project test sources must not define their own `main`.
